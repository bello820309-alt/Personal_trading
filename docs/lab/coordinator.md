# AI 模擬交易：主持人每天的流程

給主持人（Claude，在原本的對話裡）看的。每天台灣時間 15:43 左右，排程任務「AI 模擬交易：每天的操作」會在對話裡叫主持人跑一次。

原則：

- 主持人**不能給參加者任何投資建議或提示**，也不能改參加者寫的心得。只處理操作上的問題（指令錯誤、網站沒啟動、資料沒更新），以及修正網站的錯誤、補上不夠的說明（第 6 節）。
- 五位參加者（新手 A、新手 B 三檔都可以買；0050 專攻、VOO 專攻、比特幣專攻只能買自己那一檔）用**同樣的 prompt 模板**、同時開始，互相獨立。
- 為了節省用量，主持人這邊的步驟盡量合併成少數幾個指令（見第 1、5 節）。
- 所有日期都用**台灣日期**。實驗設定在 `public/lab/experiment.json`（`start`、`end`、`wrapUp`）。

## 0. 今天要不要跑

如果流程中途被打斷（例如這個對話的 worker 重新啟動），從第 1 節重新開始就好：準備指令可以重複執行，`check` 會顯示誰已經寫了今天的心得，只叫還沒寫的參加者。

- 今天在 `start` 之前：什麼都不做，只回一句「實驗還沒開始」。
- 今天在 `wrapUp` 之後：照最後一節「實驗結束之後」處理。
- 第 1 節的準備指令最後會列出大家今天的心得「已寫／還沒寫」。如果全部都已經寫了（例如排程重複觸發），不要再叫參加者操作，只要確認有 commit 和 push。

## 1. 準備（一個指令）

```bash
cd /home/user/Personal_trading && bash scripts/lab/prep.sh
```

這個指令會：
- 拉最新的程式和資料、建置網站，並在背景啟動網站（`http://localhost:4173/Personal_trading/`）
- 結算成交（`lab -- settle`），最後印出 `lab -- check` 的結果：資料日期、大家的成績、今天的進度

出問題時：
- 有未 commit 的改動：先弄清楚是什麼，不要直接丟掉。
- 建置或啟動失敗：照樣進行，告訴參加者今天網站打不開、只能用 `me` 和 `quote`，並在回報裡說明。

## 2. 確認資料有更新

`npm run -s lab -- check` 會列出每個標的最後一根 K 棒的日期。正常情況是：

- 0050：今天（平日）。
- VOO：前一個美股交易日。
- 比特幣、匯率：昨天。

資料更新的排程任務每天台灣時間 05:33、15:33 各觸發一次。Yahoo 的比特幣日 K 有時要到台灣時間 15:00～15:45 才補上（2026/11/5、11/6 都是 14:48 還沒有、15:44 就有了），所以比特幣最常落後。

如果比特幣不是昨天，或平日的 0050 不是今天：

1. 用 `mcp__github__actions_run_trigger` 觸發更新：
   - owner `bello820309-alt`，repo `Personal_trading`
   - workflow `update-and-deploy.yml`，ref `ccr-34fbc3aa-8mup3g`
   - inputs `{"only_if_changed": "true"}`
2. 等它跑完（大約 3 分鐘，用 `mcp__github__actions_list` 查），再 `git pull --rebase`。
3. 等不到也照樣繼續：成交會延到下一次。

## 3. 成交結算

第 1 節已經做了。如果第 2 節有重新更新資料，再執行一次 `npm run -s lab -- settle`。

## 4. 讓五位參加者操作

用 Agent 工具開五個 `general-purpose` 子代理：

- 在**同一則訊息**裡一起呼叫，`run_in_background: false`。
- 工作資料夾用 scratchpad 底下的 `lab/<今天>/<代號>`，先建立好。scratchpad 的完整路徑看系統提示。

| 代號 | 名字 | 可以買賣 |
|---|---|---|
| a | 新手 A | 三檔都可以 |
| b | 新手 B | 三檔都可以 |
| c | 0050 專攻 | 只有 0050 |
| d | VOO 專攻 | 只有 VOO |
| e | 比特幣專攻 | 只有比特幣（BTC） |

prompt 用下面的模板，只換掉 `<…>`。專攻的三位多加第三行，其他字五位完全一樣：

```
你是「AI 模擬交易實驗」的參加者「<名字>」（代號 <代號>）。今天是 <YYYY-MM-DD>（實驗第 <N> 天，共 30 天）。
請先完整讀 /home/user/Personal_trading/docs/lab/agent.md，照裡面的步驟完成今天的操作。
（專攻的三位才有這一行）你專攻 <標的>：只能買賣 <標的>，學習時也專心研究這一檔。
你的代號是 <代號>，每個指令的 --agent 都用它。你的工作資料夾是 <工作資料夾>（截圖和心得 JSON 放這裡）。
不要讀其他參加者的檔案，也不要讀 docs/lab/coordinator.md。完成後照說明用 10 行以內回報。
```

- 結算日（`wrapUp`）在 prompt 最後加一句：「今天是結算日，不能下單，請照說明寫整個月的總結心得。」
- 前一天有修改網站（見第 6 節）：把 `docs/lab/site-updates.md` 最新一節的「告訴參加者」那段，原封不動加在五位的 prompt 最後。
- 子代理失敗或沒有寫心得：同樣的 prompt 再叫一次（只叫那一位），並在回報裡說明。

## 5. 檢查與存檔

```bash
npm run -s lab -- check && npm run -s lab -- today
#   check：五位今天的心得都要「已寫」，最後要是「檔案檢查沒有問題」
#   today：每位今天的決定、下的單、看不懂的地方（第 6、7 節用）
git add public/lab
git commit -m "lab: 第 <N> 天（<YYYY-MM-DD>）五位新手的操作與心得" -m "<規定的結尾兩行>"
git push -u origin ccr-34fbc3aa-8mup3g
```

- commit 訊息的結尾要加對話裡規定的兩行（Co-Authored-By、Claude-Session）。
- push 失敗：先 `git pull --rebase origin ccr-34fbc3aa-8mup3g` 再推，網路錯誤最多重試 4 次（2、4、8、16 秒）。
- push 之後 GitHub 會自動部署，網站的「AI 實驗」頁幾分鐘後更新。

## 6. 檢查網站內容：有錯就修、說明不夠就補

使用者的指示（2026/11/3）：五位回報後，主持人要檢查它們的「看不懂」和回報裡提到的網站問題，**當天就改好、上線，再在回報裡告訴使用者**。網站每天改進，大家隔天才能用新的說明學習；不然它們會一直照著錯的或看不懂的內容操作，測試就沒有意義。

- 每一項都要到網站、程式和資料裡確認，不能只看參加者的說法。
- **網站有錯**：直接修正。例如：
  - 數字或計算錯誤、程式 bug
  - 說明和畫面上實際顯示的不一致
  - 對狀態的描述和資料不符（例如明明在跌卻說是盤整）
  - 前後的說法真的互相矛盾，其中一個是錯的
- **說明不夠**：直接補上說明。例如：
  - 新手看不懂某個名詞、數字或圖
  - 不知道兩頁的數字為什麼不一樣
  - 兩種方法的說法看起來相反
  - 不知道某個功能怎麼套用到自己的情況
- 不改的：
  - 對行情的看法、要不要買賣的判斷
  - 和網站內容無關的抱怨

  這些在回報裡提一下就好。
- 怎麼改：
  - 補在新手會看到的地方：卡住的那一頁、那一段，必要時在相關的頁面互相提到。
  - 用網站一貫的白話寫法，寫給完全不懂的人看。
  - 有計算或判斷邏輯的修改要補測試。`npm test`、`npm run typecheck`、`npm run build` 都要通過，再用 `npm run -s lab:browse` 確認畫面上真的看得到。
  - 和當天的實驗紀錄分開 commit，訊息寫「網站修正：…」或「網站說明：…（第 N 天新手回報）」，然後 push。
  - 不能變成投資建議，不能談現在的行情該怎麼做，也不能只對某一位參加者有利（大家看到的永遠是同一個網站）。
- 改完把當天的修改寫進 `docs/lab/site-updates.md` 最上面：改了什麼、是哪一位回報的，以及一段給參加者看的「告訴參加者」。隔天叫五位操作時，把這段原封不動加在五位的 prompt 最後（五位一樣）。
- 檢查完（有沒有修改都一樣），停掉背景的網站：`pkill -f "[v]ite preview"`。

## 7. 回報使用者

用繁體中文，簡短：

- 第 N 天（日期）
- 五位各一行：今天做了什麼（一句）、總資產與報酬；專攻的三位加上「同一檔分批買進不動」的報酬當比較
- 買了不動（對照）：總資產與報酬
- 網站修正：哪些是錯誤、改了什麼、是哪一位回報的（沒有就不寫）
- 補上的說明：補了什麼、補在哪一頁、是哪一位看不懂（沒有就不寫）
- 沒有改的回饋：為什麼不改（有的話）
- 有任何問題也要說（資料沒更新、指令錯誤、子代理失敗）
- 最後另外一段「分析師追蹤」（和實驗無關，見 `docs/analysts.md`）：執行 `npm run -s analysts -- --since <昨天回報的時間>`，有新影片就列標題（提醒使用者想看重點可以貼逐字稿），預測的狀態有變（說對、說錯、條件成立）就說一聲；都沒有就寫一行「沒有新影片」。

不要評論誰做得對、誰做得錯，也不要預測行情。

## 實驗結束之後

`wrapUp` 那天照常跑完（參加者寫總結），然後：

1. 寫一份整個月的總結給使用者：
   - 三方的最後成績
   - 五位做法的差異（三檔都買 vs. 專攻一檔、和各自的對照比）
   - 大家學到的東西
   - 實驗期間修正的錯誤、補上的說明
   - 網站還可以改進的地方
2. 用 `mcp__claude-code-remote__list_triggers` 找名稱「AI 模擬交易：每天的操作」的排程任務，再用 `update_trigger` 把它停用（`enabled: false`）。
3. 告訴使用者排程已經停了。
